hey-notmuch

“hey! not much” — read your HEY (hey.com) email through notmuch. A public Emacs package.

1 · Goal

HEY has no IMAP. The official hey CLI exposes boxes, postings, threads, seen-state, and composition over JSON. hey-notmuch is a distributable Emacs package that synthesizes RFC822 mail from the CLI's JSON into a local maildir so notmuch can index it — plus reply/compose, read-state write-back, and saved-search integration.

Deliverables: (a) a standalone GitHub repo (ovistoica/hey-notmuch) with README setup instructions, CI, and MELPA-ready packaging; (b) your personal config consuming it via use-package :vc.

┌──────────────┐ hey box <b> --json ┌──────────────────────────┐ notmuch new ┌───────────────┐ │ hey CLI │ hey threads <id> --json │ hey-notmuch.el (sync) │ + tagging │ notmuch │ │ (HEY API) │ ───────────────────────► │ pure elisp; runs in a │ ──────────────► │ Emacs (MUA) │ │ │ ◄─────────────────────── │ batch-Emacs subprocess │ │ │ └──────────────┘ hey seen <posting-id> │ → ~/.mail/hey/… │ ◄────────────── └───────────────┘ hey reply <topic> -m └──────────────────────────┘ read-state hook, same entrypoint works reply via hey CLI from systemd / cron
Key architecture (rev 3): the sync engine is a bash + jq script (bin/hey-notmuch-sync) shipped inside the package repo — mirroring the owner's existing mbsync systemd pattern (oneshot service + timer), which it will eventually replace once all accounts are forwarded to HEY. Dependencies: bash, jq, hey CLI, notmuch. The Elisp side (hey-notmuch.el) provides the notmuch UX and runs the script asynchronously from M-x hey-notmuch-sync; systemd runs the same script directly, exactly like ExecStart=mbsync -a does today.

4.3 · Sync engine (pure Elisp, mirrors the validated prototype)

Same synthesis spec as validated during recon — one RFC822 file per HEY thread entry:

HeaderValuePurpose
Message-ID<hey-entry-{entry-id}@hey-notmuch.local>Stable identity; dedup on re-sync
In-Reply-To / ReferencesMessage-ID chain of prior entriesCorrect notmuch threading
From"{name}" <{email or hey-contact-{id}@hey-notmuch.local}>Feed senders often lack email_address — deterministic fallback
Subjectposting name, Re: for entries > 1, RFC2047 when non-ASCII—
DateISO8601 → RFC2822—
X-Hey-Topic-Id · X-Hey-Posting-Id · X-Hey-Box · X-Hey-App-Urlfrom postingReply + seen write-back + browser jump
Bodytext/plain; charset=utf-8HTML → v2
  • Maildir: {maildir}/{box}/{new,cur,tmp}; seen (observed_at set) → cur/…:2,S, unseen → new/. With maildir.synchronize_flags=true, unread is derived for free.
  • Idempotency: state file {maildir}/.hey-notmuch-state.eld maps posting-id → (updated-at . entry-ids); unchanged postings skip the thread fetch entirely; entries are written at most once.
  • Tagging: after notmuch new: +hey +hey/imbox for path:hey/imbox/**; feed/papertrail additionally -inbox. Idempotent (guarded by not tag:hey).
  • Errors: per-posting failures log to stderr and never abort the sync; missing hey binary or failed auth → clear user-error with remediation hint (hey auth login).
  • Elisp structure: pure functions for parsing/synthesis (hey-notmuch--topic-id, hey-notmuch--entry-rfc822, hey-notmuch--rfc2047, hey-notmuch--from-header…) — all unit-testable without network; effectful shell layer isolated in hey-notmuch--hey-json / hey-notmuch--notmuch.

4.4 · README setup instructions (outline shipped with the repo)

# hey-notmuch — “hey! not much”

Read your HEY email through notmuch, in Emacs.

## Requirements
- Emacs 29+ with notmuch.el
- notmuch CLI
- hey CLI: https://github.com/basecamp/hey-cli  (run `hey auth login` once)

## Install
;; use-package + vc (Emacs 30) — MELPA planned
(use-package hey-notmuch
  :vc (:url "https://github.com/ovistoica/hey-notmuch")
  :after notmuch
  :config (hey-notmuch-setup))

## Notmuch prerequisites
Your maildir root must contain the hey-notmuch maildir
(default `~/.mail/hey` — customize `hey-notmuch-maildir`), and
`maildir.synchronize_flags` should be `true` for read-state mapping.

## First sync
M-x hey-notmuch-sync          ; or from a shell / timer:
emacs -Q --batch -l hey-notmuch.el -f hey-notmuch-sync-batch

## Automation (systemd user timer)
cp contrib/hey-notmuch-sync.{service,timer} ~/.config/systemd/user/
systemctl --user enable --now hey-notmuch-sync.timer

## Keybindings (installed by hey-notmuch-setup)
notmuch-show:  C-c C-h r  reply via HEY     C-c C-h o  open in browser
notmuch-hello: G          sync

6.1 · Sync engine core (excerpt)

hey-notmuch.el (excerpt — pure functions + batch entrypoint) 
;;; hey-notmuch.el --- Read HEY email through notmuch -*- lexical-binding: t; -*-

;; Author: Ovidiu Stoica <ovidiu.stoica1094@gmail.com>
;; URL: https://github.com/ovistoica/hey-notmuch
;; Version: 0.1.0
;; Package-Requires: ((emacs "29.1") (notmuch "0.38"))
;; Keywords: mail

;;; Commentary:
;; “hey! not much” — synthesizes RFC822 maildir messages from the HEY
;; CLI's JSON output so notmuch can index your HEY mail.  Provides
;; sync, reply/compose via the hey CLI, read-state write-back, and
;; notmuch saved-search integration.  See README for setup.

;;; Code:

(defun hey-notmuch--topic-id (posting)
  "Extract the topic id from POSTING's app_url, or nil."
  (when-let* ((url (gethash "app_url" posting)))
    (and (string-match "/topics/\\([0-9]+\\)" url)
         (string-to-number (match-string 1 url)))))

(defun hey-notmuch--rfc2047 (s)
  "RFC2047-encode S when it contains non-ASCII characters."
  (if (string-match-p "[^[:ascii:]]" s)
      (format "=?UTF-8?B?%s?=" (base64-encode-string (encode-coding-string s 'utf-8) t))
    s))

(defun hey-notmuch--from-header (entry)
  "Build a From header for ENTRY with deterministic address fallback."
  (let* ((creator (gethash "creator" entry))
         (alt     (gethash "alternative_sender_name" entry))
         (name    (or (and alt (not (string-empty-p alt)) alt)
                      (gethash "name" creator "Unknown")))
         (email   (let ((e (gethash "email_address" creator "")))
                    (if (string-empty-p e)
                        (format "hey-contact-%s@hey-notmuch.local"
                                (gethash "id" creator 0))
                      e))))
    (format "%s <%s>" (hey-notmuch--rfc2047 name) email)))

(defun hey-notmuch--hey-json (&rest args)
  "Run the hey CLI with ARGS --json; return parsed :data or signal."
  (with-temp-buffer
    (let ((status (apply #'call-process hey-notmuch-executable nil t nil
                         (append args '("--json")))))
      (unless (eq status 0)
        (error "hey %s failed (%s) — try `hey auth login'?"
               (string-join args " ") status))
      (let* ((env (json-parse-string (buffer-string)))
             (ok  (gethash "ok" env)))
        (unless (eq ok t)
          (error "hey %s returned not-ok" (string-join args " ")))
        (gethash "data" env)))))

;; … entry→rfc822, maildir write, state, tagging: per spec §4.3 …

;;;###autoload
(defun hey-notmuch-sync-batch ()
  "Sync HEY mail into the notmuch maildir.  Blocking batch entrypoint."
  (dolist (box hey-notmuch-boxes)
    (hey-notmuch--sync-box box))
  (hey-notmuch--index-and-tag))

;;;###autoload
(defun hey-notmuch-sync ()
  "Sync HEY mail asynchronously via a batch Emacs subprocess."
  (interactive)
  (message "hey! syncing…")
  (make-process
   :name "hey-notmuch-sync"
   :buffer " *hey-notmuch-sync*"
   :command (list (expand-file-name invocation-name invocation-directory)
                  "-Q" "--batch" "-l" (locate-library "hey-notmuch")
                  "-f" "hey-notmuch-sync-batch")
   :sentinel #'hey-notmuch--sync-sentinel))
